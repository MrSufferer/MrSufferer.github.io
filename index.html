04 /

Verifiable randomness

Kamui

VRF architecture

Verifiable randomness with a clear request-to-result lifecycle.

The proposed architecture binds each request to a future drand beacon. An oracle waits for that round, submits an ECVRF proof, and the program verifies it before delivering randomness to the application.

Engineering scope

The specification includes fee escrow, callback delivery, a query fallback, and refunds for requests that time out.

05 /

On-chain perpetual futures

MGK Exchange

Batch-auction exchange

Perpetual futures with batch-auction matching on Solana.

Orders collect within a batch, clear through a dual-flow auction, and settle on-chain. Separate Rust programs handle custody and positions, matching, and the fallback oracle, alongside a TypeScript SDK, keeper, indexer, and trading interface.

Engineering scope

Matching logic, cross-margin portfolios, persistent orders, liquidation handling, and the batch settlement lifecycle.
